# 7 · 规矩要变成闸

[English](../07-rules-become-gates.md) · **中文**

我有一条内容方面的规矩，登记的档位是「定时查」。检查登记表的脚本去找执行它的脚本，发现根本不存在。这条规矩在文件里躺了快两周，根本没人在执行它。

我那些失效的规矩，基本是两种死法。一种是规矩只写在 agent 的说明里，头一周管用，后来说明越写越长，这条被一眼扫过去，老毛病又回来了。另一种是执行它的脚本被人重写了，规矩还写在那儿，却已经没人在查。

## 档位

每条规矩在定下的当天就要写明自己是哪一档：

| 档位 | 意思 |
|---|---|
| `gate`（机器挡） | 机器直接拦下错误动作：钩子、提交前检查、CI 步骤 |
| `scheduled`（定时查） | 有任务按时检查，并报出来 |
| `advisory`（靠自觉） | 全凭自觉，登记表上照实写明 |

- 机器挡和定时查的规矩，要写明由哪个文件执行，再写一个必须出现在这个文件里的标记字符串。
- 没有东西真的在拦，就别标成机器挡。假闸会让所有人以为问题已经管住了，于是没人再盯。
- 每件事实只放在一个文件里，别处都只放链接。手抄的副本迟早对不上。
- 改规矩或脚本之前，先列出下游所有读它的地方；改完逐个核对。
- 每次开会话都会加载的说明文件（比如 CLAUDE.md）要短。我的控制在 200 行左右，再长就会被一眼扫过去。

模板：[`templates/ops/RULES-REGISTRY.json`](../../templates/ops/RULES-REGISTRY.json)。模板里的规矩一开始都是 `advisory`（R-01 除外，`dispatch.py` 自己会执行），每条的备注写着要先接好什么，才能升档。

## 怎么检查

```bash
python3 scripts/rules_check.py
```

```
4 rules: 3 gate · 0 scheduled · 1 advisory
✗ R-06: enforcer scripts/link_gate.py does not exist — Posts with broken links never ship
```

每个会话开工时跑一次，哪道闸死了，当天就能发现。它检查的是执行脚本还在、里面还有你选的那个标记字符串（比如一个函数名）。它证明不了脚本真的接进了钩子，这一步还得你自己核。

## 目前的结果

<p align="center"><img src="../../docs/tiers.zh-CN.svg" alt="我的 170 条规矩按档位分：机器挡 82 条（48%），定时查 41 条（24%），靠自觉 47 条（28%）。" width="760"></p>

总部加四位负责人，一共登记了 170 条规矩。82 条写明了由哪个脚本拦（48%），41 条定时查（24%），47 条靠自觉（28%）。开头那条内容规矩也算在靠自觉里，等有人写出检查它的脚本才能升档。
